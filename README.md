Создай Python-проект из ДВУХ приложений:
1) main.py — конфигуратор сборок АКБ (главное приложение).
2) add_cell.py — GUI-приложение для добавления ячеек в базу.

Проект брендируется "RD". Логотип — SVG-файл logo.svg в корне проекта.
Общая база — текстовый файл cells_db.txt (UTF-8).
Тема — светлая. Шрифт — "GOST type A" (с fallback на системный sans).
Все единицы подписывать: Вт, Вт·ч, А·ч, В, А, мм, °C, ч, %.
Все габариты округлять до 0.1 мм.

ОБЩЕЕ: СТРУКТУРА БАЗЫ cells_db.txt
════════════════════════════════════════════════════════

Разделитель полей — ";". Первая строка — заголовок. Десятичный
разделитель — точка. Заголовок строго такой:

наименование;бренд;тип_химии;тип_формы;длина_мм;ширина_мм;высота_мм;емкость_Ач;напряжение_ном_В;напряжение_мин_В;напряжение_макс_В;макс_ток_разряда_А;макс_ток_заряда_А;мин_темп_разряда;макс_темп_разряда;масса_г;внутр_сопротивление_мОм;циклов;емкость_после_1000_циклов_%

Правила:
- тип_формы: "C" (цилиндр) или "P" (призма / pouch).
- C: длина_мм — вдоль оси, ширина_мм = высота_мм = диаметр.
- P: длина_мм, ширина_мм, высота_мм — три габарита корпуса.
- Пустые необязательные поля допускаются.
- Битые строки — пропускать с предупреждением в консоль.
- Если cells_db.txt отсутствует или пуст — создать с заголовком.

Пример строки:
Samsung INR21700-50E;Samsung;Li-Ion;C;70.2;21.1;21.1;4.9;3.6;2.5;4.2;9.8;4.9;-20;60;70;20;1000;85

════════════════════════════════════════════════════════
ЛОГИКА РАСЧЁТА (main.py)
════════════════════════════════════════════════════════

Базовая ячейка: E_яч = Uном × C_яч (Вт·ч).

Сборка nS × mP (n последовательных, m параллельных):
- Число ячеек N = n × m.
- E_сборки = E_яч × N (Вт·ч).
- Ёмкость = C_яч × m (А·ч).
- Напряжение = Uном × n (В).
- Макс ток разряда сборки = макс_ток_разряда_ячейки × m (А).
- Время работы = E_сборки / нагрузка_Вт (ч).

Температура, циклы, ёмкость после 1000 циклов — только справочно,
в расчёте НЕ участвуют.

Цель: время работы ≥ t_треб.

Ограничения поиска (жёстко):
- S ≤ 100, P ≤ 100, N = S·P ≤ 400.
- Число слоёв по высоте сборки ≤ 3.
- Округление размеров до 0.1 мм.
- Все линейные размеры в мм.

───── Стратегия поиска ─────

ШАГ 1. Сгенерировать все пары (n, m) с n·m ≤ 400, n ≤ 100, m ≤ 100.
Отсортировать по:
  (1) n·m по возрастанию,
  (2) объём сборки по возрастанию,
  (3) n по возрастанию.

ШАГ 2. Пройти по списку. Для каждой пары:
  a) Проверить электрику: время работы ≥ t_треб.
     Если нет — пропустить пару, продолжить.
  b) Если чекбокс "Учитывать габариты" СНЯТ:
       - ориентация по умолчанию "стоит";
       - габариты посчитать справочно, не отбраковывать.
       - пара проходит, зафиксировать.
  c) Если чекбокс ВКЛЮЧЁН:
       - перебрать все подходящие раскладки N ячеек в 3D-сетку
         (a × b × c), где a·b·c ≥ N и c ≤ 3;
         предпочтительная раскладка — с минимальным объёмом;
         для каждой раскладки перебрать 6 ориентаций корпуса
         (перестановки осей X/Y/Z, см. ниже);
         собрать список физически возможных габаритов сборки;
       - для каждого варианта проверить, влезает ли он в заданные
         Д×Ш×В с учётом:
           • зазор между ячейками (см. ниже),
           • место под BMS,
           • толщина стенок корпуса с каждой стороны,
           • допуск вырезания % (расширяет целевую коробку на этот %).
       - если хотя бы один вариант влезает — пара проходит,
         фиксируем лучший (минимальный объём).
       - если ни один не влезает — пара отбрасывается, продолжить.

ШАГ 3. Собрать до 10 прошедших пар в результат.
Если прошедших < 3 — добавить из отброшенных:
  - сначала по времени (ближайшие к t_треб по убыванию),
  - затем по габаритам (наименьшее превышение).
Пометки "⚠ не проходит по …" для неполных вариантов.

ШАГ 4. Если вообще ни один вариант не проходит по времени —
вывести 1 наиболее близкий по времени с пометкой "⚠".

ШАГ 5. Из финального списка выделить три характерных варианта
и промаркировать визуально (например, меткой на кнопке):
  - максимальный S (упор на напряжение),
  - максимальный P (упор на ток/ёмкость),
  - сбалансированный (ближе всего к N/2 × N/2 по осям).

───── Раскладка N ячеек в 3D ─────

Раскладка — это тройка (a, b, c), где a·b·c ≥ N, c ≤ 3.
Оставшиеся пустые места в последнем слое — допустимы (не заполнены).
Из всех троек, дающих N ячеек, брать те, где:
  - нет пустых мест, если возможно,
  - иначе — минимум пустых мест.
Затем из подходящих троек — минимальный объём сборки.

───── 6 ориентаций корпуса ─────

Сборка как коробка Д×Ш×В (внутренние оси). Ячейки укладываются
в 3D-сетку (a, b, c). Ориентация ячейки относительно коробки:
у ячейки есть три собственные оси:
  - ось длины L (длина_мм),
  - ось ширины W (ширина_мм),
  - ось высоты H (высота_мм).
При этом W = H для цилиндра.
Перебрать ВСЕ 6 перестановок (L, W, H) → (X, Y, Z) целевой коробки.
Для каждой — посчитать, влезает ли.
Пример: ячейка 18650 (L=65, W=18, H=18):
  1) L→X, W→Y, H→Z: длина сборки 65a, ширина 18b, высота 18c.
  2) L→X, W→Z, H→Y: 65a, 18c, 18b.
  3) L→Y, W→X, H→Z: 18b, 65a, 18c.
  4) L→Y, W→Z, H→X: 18b, 18c, 65a.
  5) L→Z, W→X, H→Y: 18c, 65a, 18b.
  6) L→Z, W→Y, H→X: 18c, 18b, 65a.
Именно эти 6 ориентаций (сокращённо — перестановки) проверять.

───── Зазор между ячейками ─────

Зазор задаётся пользователем в мм (слайдер 0–10).
Внутри ряда из k ячеек вдоль оси — (k−1) зазоров.
Снаружи ряда зазора нет (там стенка корпуса).
Итог: длина ряда = k·размер_ячейки + (k−1)·зазор.

───── Место под BMS ─────

Пользователь задаёт BMS_мм (0–50).
Это резерв вдоль одной из трёх осей сборки.
Автоматически выбирается та ось, где после резерва остаётся
наибольший запас места (т.е. где потеря наименее критична).
На чертеже показывается отдельной заштрихованной зоной.

───── Толщина стенок корпуса ─────

Пользователь задаёт wall_мм (по умолчанию 0).
Вычитается из целевых габаритов С КАЖДОЙ стороны:
реальный доступный объём = (Д − 2·wall) × (Ш − 2·wall) × (В − 2·wall).

───── Допуск вырезания ─────

Пользователь задаёт cut_% (0–100, по умолчанию 0).
Целевые габариты расширяются на этот процент:
Д_eff = Д · (1 + cut_%/100), аналогично Ш_eff, В_eff.
Применяется только при включённом чекбоксе "Учитывать габариты".

───── Поведение при "не влезает" ─────

Если при включённом чекбоксе ни один вариант не влезает —
вывести сообщение "Ни одна сборка не влезает в заданные габариты".
Справочно показать до 3 наиболее близких вариантов
с пометкой:
  "⚠ превышение по ширине на 12.4 мм" (указать ось и величину).
Также показать наиболее близкий по времени.

ОТРИСОВКА СБОРОК
════════════════════════════════════════════════════════

- Ячейка — толстая СЕРАЯ линия по контуру на белом фоне.
- Между ячейками — БЕЛЫЙ зазор (толщина линии) + регулируемый зазор.
- Общие габариты — КРАСНАЯ линия.
- Подписи ширины/глубины/высоты — СНАРУЖИ габаритов.
- Если чекбокс "Учитывать габариты" включён — ЗЕЛЁНЫЕ линии
  целевых габаритов, а также заштрихованная зона под BMS.
- Масштаб автоматический, при ресайзе окна — пропорционально,
  но не мельче читаемого (минимальный размер ячейки на экране ~ 6 px).

Как рисовать ячейку:
- Форма C (цилиндр):
  - Вид спереди: "стоит" → круг Ø = ширина_мм; "лежит" →
    прямоугольник (длина × ширина_мм).
  - Вид сбоку: "стоит" → прямоугольник (ширина × длина);
    "лежит" → прямоугольник (длина × ширина).
- Форма P (призма):
  - Вид спереди: прямоугольник (ширина × высота).
  - Вид сбоку: прямоугольник (длина × высота).
